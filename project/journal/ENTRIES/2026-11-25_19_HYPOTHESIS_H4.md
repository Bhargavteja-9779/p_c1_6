# HYPOTHESIS H4 — 2026-11-25 — written BEFORE the diagnostic and before any method run
Mechanism ("self-shielding"): in the contaminated regime, training anomalies sit close to test anomalies (anomalies of one dataset share a generating process), so a test anomaly finds anomalous training neighbours and gets a small k-distance → low score.
Falsifiable predictions on DEV datasets, seeds 0–2, contaminated regime:
P1. For most datasets, the share of test anomalies whose 1st nearest TRAINING neighbour is a training anomaly ("shield rate") is far above the anomaly rate (else the mechanism is absent).
P2. Across datasets, the kNN AUROC drop (clean − contaminated) correlates positively with the shield rate (Spearman ρ > 0.4). If ρ ≤ 0.4, the drop is mostly something else (e.g. fewer clean training points, different test sets).
P3. ORACLE check (diagnostic only, uses training labels, never a method): removing the training anomalies from the contaminated training set recovers most (> 50 %) of the kNN drop. If not, self-shielding is not the main cause.
If P1–P3 hold, the method must estimate which training points are anomalous WITHOUT labels and stop them from shielding (e.g. trust weights from leave-one-out outlyingness within the training set), and must leave the clean regime unchanged.
Novelty note (prior art in literature/prior_art_v2/tabular_ad.md): ZEN/FOCUS trust-weight neighbours in TabPFN embedding space (GPU); subsampled kNN ensembles (Aggarwal & Sathe 2015) reduce masking — both must be baselines.
