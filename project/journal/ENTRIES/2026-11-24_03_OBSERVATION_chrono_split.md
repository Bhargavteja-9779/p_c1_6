# OBSERVATION — 2026-11-24 — a chronological split is really an "unseen attack" split
After making 60/20/20 chronological splits (data/proc/prep_report.json, first version) I looked at which attacks land where. In NF-ToN-IoT-v3 the training period contains ddos/scanning/injection/dos, the validation period contains password and xss (never seen in training), and the test period is dominated by xss and backdoor. In NF-CSE-CIC-IDS2018-v3, validation is 98 % benign plus Infiltration, test is Bot + Infiltration — none of which appear in training. In NF-BoT-IoT-v3 the val/test periods are >99.9 % DDoS with only 3 and 36 benign flows.
So a "temporal" split on these captures does not measure drift of the same attacks; it measures detection of attack families that were never seen. I changed the plan: keep the chronological split as an analysis lens (RQ1), but build the cross-network (leave-one-dataset-out) protocol on random within-dataset pools, so that the shift being measured is the change of network, not the change of attack family. BoT-IoT as a *target* has ~0.3 % benign flows, which makes macro-F1 unstable; I pre-register it as reported-separately (primary metric = mean over UNSW, ToN, CIC targets). Decision D11.
